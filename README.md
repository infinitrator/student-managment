# Лабораторная №1 — «Управление студентами»

Многостраничный frontend-проект без фреймворков и runtime-зависимостей. Данные сохраняются в cookies, интерфейс адаптируется под телефон и компьютер, а относительные ссылки позволяют публиковать проект на GitHub Pages. Node.js-пакеты используются только разработчиком для линтинга и тестов.

## Страницы

- `index.html` — список, поиск, статистика и удаление;
- `student-form.html` — добавление нового студента;
- `student-form.html?id=ID` — редактирование выбранного студента;
- `student-profile.html?id=ID` — подробный профиль студента.

ID передаётся через query-параметр, потому что GitHub Pages раздаёт только статические файлы и не поддерживает серверные динамические маршруты.

## Возможности

- полный CRUD;
- отдельные страницы списка, формы и профиля;
- автоматическое заполнение формы редактирования;
- HTML- и JS-валидация;
- проверка уникальности ИСУ ID;
- хранение массива студентов в разбитых на части cookies;
- полная поддержка кириллицы и букв `Ё/ё` в форме, поиске и cookies;
- стандартные JSDoc-комментарии для функций и модулей JavaScript;
- ES-модули и закрытое состояние бизнес-логики;
- Content Security Policy и безопасный вывод через `textContent`;
- повторная проверка данных после чтения cookies и перед записью;
- линтинг JavaScript, HTML и CSS;
- адаптивная таблица, форма и профиль;
- три тестовые записи при первом запуске;
- favicon-котик;
- готовность к GitHub Pages без сборки.

## Локальный запуск

```bash
cd ~/build/student-managment
python3 -m http.server 8000
```

Открыть `http://localhost:8000`. Через `file://` запускать нельзя, потому что работа cookies в таком режиме ненадёжна.

## Проверка качества

Один раз установить инструменты разработки:

```bash
npm install
```

Запустить полный линтинг и тесты:

```bash
npm run lint
npm test
```

ESLint проверяет JavaScript, JSDoc и потенциально опасные DOM-операции. HTML Validate проверяет разметку, Stylelint — CSS, Prettier — единое форматирование. Интеграционный тест проверяет валидацию, CRUD, cookies, кириллицу и отклонение повреждённых данных.

## Хранение в cookies

Массив сериализуется в JSON, кодируется в UTF-8/Base64 и делится на части по 3000 символов. Количество частей хранится в отдельной meta-cookie и ограничено двадцатью. Cookies живут один год, получают `SameSite=Lax`, `Secure` на HTTPS и путь текущей папки сайта. Сервис хранит не больше 20 записей, чтобы даже записи с максимально длинными Unicode-полями помещались в заданный объём, и проверяет типы, допустимые поля, уникальность ID и ИСУ ID.

Base64 нужен только для корректной кириллицы и не является шифрованием. Cookies доступны владельцу браузера, поэтому проект нельзя использовать для настоящих секретных или централизованных персональных данных.

## Безопасность

Пользовательские значения никогда не передаются в `innerHTML`: интерфейс использует `textContent`. Адреса строятся только для двух разрешённых HTML-страниц через `URLSearchParams`. Content Security Policy запрещает сторонние скрипты, объекты, фреймы и сетевые запросы. Повреждённые или подменённые cookies считаются недоверенными, фильтруются и не попадают в DOM без повторной проверки.

## Публикация на GitHub Pages

1. Загрузить содержимое проекта в корень репозитория GitHub.
2. Открыть **Settings → Pages**.
3. В разделе **Build and deployment** выбрать **Deploy from a branch**.
4. Выбрать ветку `main` и папку `/(root)`.
5. Нажать **Save** и дождаться публикации.

Дополнительная сборка, Node.js и GitHub Actions не требуются. Все ссылки относительные, поэтому сайт работает по адресу вида `https://username.github.io/student-managment/`.

## Ограничения

Cookies хранятся отдельно в каждом браузере и не синхронизируются между устройствами. Это учебное хранилище, а не серверная база данных. GitHub Pages является статическим хостингом и не может скрывать или централизованно сохранять персональные данные.
